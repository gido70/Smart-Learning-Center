# سير عمل الأتمتة الآمن

يوضح هذا المستند المسار الأساسي المقترح لأي تعديل على مركز التعلّم الذكي، بحيث لا يصل أي تغيير إلى الفرع `main` قبل اختباره ومراجعته.

## المسار المعتمد

**طلب التعديل ← فرع آمن ← اختبار ← مراجعة عبدالرحمن ← دمج ← نشر**

### 1. طلب التعديل

يبدأ العمل بطلب واضح يحدد الهدف والملفات أو الوظائف المتأثرة والقيود التي يجب الالتزام بها.

### 2. فرع آمن

يُنشأ فرع مستقل من آخر نسخة معتمدة، ولا يتم تنفيذ العمل مباشرة على `main`. يجب أن يحمل الفرع اسمًا يوضح الغرض منه، مثل `feature/<name>` أو `fix/<name>` أو `automation/<name>`.

### 3. الاختبار

قبل طلب الدمج تُشغّل فحوصات المشروع محليًا:

```bash
python tests/smoke_test.py
python scripts/check_release.py
```

وعند فتح Pull Request إلى `main` أو تحديثه، يشغّل GitHub Actions الفحصين نفسيهما تلقائيًا. لا ينتقل التعديل إلى المراجعة النهائية إذا فشل أي فحص.

### 4. مراجعة عبدالرحمن

يراجع عبدالرحمن ملخص التغيير والملفات المتأثرة ونتائج الاختبارات، ثم يقرر الموافقة أو يطلب تعديلات إضافية. نجاح الاختبارات لا يستبدل المراجعة البشرية.

### 5. الدمج

لا يُدمج الفرع في `main` إلا بعد نجاح الفحوصات والحصول على موافقة عبدالرحمن. يجب التأكد قبل الدمج من أن نطاق التغيير يطابق الطلب ولا يتضمن ملفات غير مقصودة.

### 6. النشر

يأتي النشر بعد الدمج المعتمد فقط، ويُنفذ كخطوة مستقلة يمكن التحقق منها أو التراجع عنها. إنشاء الفرع أو نجاح الاختبارات أو فتح Pull Request لا يعني السماح بالنشر تلقائيًا.

## ضوابط أساسية

- لا تعديل مباشر على `main`.
- لا دمج عند فشل أي اختبار.
- لا دمج أو نشر دون موافقة عبدالرحمن.
- لا تُحفظ مفاتيح أو كلمات مرور داخل ملفات المستودع أو سجلات الأتمتة.
- يقتصر كل Pull Request على التغيير المطلوب قدر الإمكان لتسهيل المراجعة والتراجع.
